# LTS 流程卡住治理同步说明

本分支补齐 3.24.13–3.24.16 已发布的诊断和运行时修复，以 4.0.5 中经过适配的实现为来源。

- 诊断规则排除正常暂停、冻结、失败等待人工处理、等待外部回调和正常网关收敛；扫描默认只考虑近 7 天仍有活动的流程。
- 旧引擎在取得调度锁后重新读取回调状态，保留前一回调已提交的输出和计数，并避免重新保存已结束的调度；同步 4.0 LTS 的 `0d7a372` 修复。
- 子进程 ACK 通过 `dead=False` 的原子更新去重，避免重复 ACK 影响当前或后续并行分支。
- 单次回调锁冲突重试由服务的 `callback_lock_retryable` 显式允许，默认关闭；允许时最多重试 3 次，保留原回调数据和路由头。
- 本次不引入 `pipeline.contrib.reliable_events` 的 SHADOW/ACTIVE 回调补偿功能，也不变更包版本与依赖锁定。

## 与表达式安全检查的关系

诊断规则不执行流程表达式；事件记录和告警失败会被隔离，不应阻止业务调度。ACK 去重只改变同一子进程的重复完成通知。回调重试仍经当前分支原有的调度与渲染路径，保留版本、节点状态和调度锁检查。

本次不以旧分支的表达式实现覆盖 3.24/4.0 的最新安全实现。3.29/5.0 尚未包含 3.24/4.0 的整套最新 Mako 子进程安全改动；本次治理同步不代表该安全差异已经消除。

## 接入与开关

使用诊断数据模型的应用需注册 `pipeline.contrib.diagnostics` 并执行该应用的迁移；不要仅凭升级包版本认定扫描或治理已开启。

库中 `PIPELINE_DIAGNOSTICS_EVENT_ENABLED`、`SCAN_ENABLED`、`CASE_ENABLED`、`ALERT_ENABLED` 的默认值为 `True`；`APPLY_ENABLED` 和 `BATCH_OPERATION_ENABLED` 默认 `False`。观察事件、周期扫描和主动写操作是独立配置，应用如需灰度应显式设置。定时扫描需要应用配置调用入口，本补丁不会向现网自动添加 Beat 任务。

可靠事件主动补偿应另行审核：既存 ACTIVE 事件的消费路径并未重新检查 ACTIVE 开关，不能把关闭采集开关当作已排队重放的停止保证。
